## Recurring pattern: what Claude should catch without being told

Across this session and the one before it, Ariba repeatedly had to be the one to spot padding/margin/consistency issues that should have been caught before she ever saw them — this happened often enough that it's a pattern worth naming, not just individual bugs. The common thread: changes got verified in isolation (does *this* section look right?) rather than in context (does this section match its neighbors, and does this same component look right at every breakpoint, on every page it appears on?).

Before calling a change "done," run this checklist — not just for the thing you touched, but for its neighbors and its siblings elsewhere in the codebase:

1. **Check the same component/pattern on every page it appears on, not just the one you were asked about.** Testimonials, Trusted-By logos, closing CTAs, and section padding all exist on multiple pages as near-duplicate components. A fix applied to one and not the others is exactly how this session's bugs kept happening — e.g. `WwmTestimonials` never got the padding tightening `Testimonials.tsx` got, for two sessions running, until Ariba caught it a second time.
2. **Check all three breakpoints, not just the one being discussed.** A mobile fix can leave tablet or desktop untouched and now the odd one out (this happened repeatedly: mobile got fixed, tablet didn't, then tablet got fixed and desktop's base value was still stale).
3. **Measure, don't eyeball.** Padding/height "looks consistent" is unreliable from a screenshot. Use `javascript_tool` to read `getComputedStyle().paddingTop` (or card `getBoundingClientRect().height` for card grids) across every section/card at once, at each breakpoint. This is how every real bug this session was actually confirmed, not just felt.
4. **When a design pattern is copy-pasted to a sibling component, re-derive the numbers, don't just copy them.** The testimonial "shortest quote shows fully" pattern broke on `WwmTestimonials` because that component uses a bigger font and wider padding than the original it was copied from — the same character-count threshold didn't produce the same result. Any ported pattern needs its own verification pass in its new context.
5. **After a multi-file batch of similar fixes, grep for the pattern across the whole codebase** to confirm every instance got it, not just the ones that came up in conversation. (e.g. `grep -rn "max-\[700px\]:pt-20"` was how the mobile-padding rollout confirmed it caught all 21 instances, not just the ones on the page being discussed at the time.)

## Key decisions to carry forward

- **Section-opening padding standard: 70px mobile / 96px tablet (max-[1024px]) / 120px desktop**, applied consistently across all four pages. See "What happened this session" above for the specific exceptions that deliberately stay off this rhythm (Positioning-style intro paragraphs, compact interstitial bands, centered layouts).
- **A structural layout bug can look identical to a styling inconsistency.** The "sections feel randomly spaced" complaints this session were actually caused by flex-wrap layouts collapsing to a mobile-like stack somewhere in the 700–1024px tablet range while still using desktop padding — not by careless value choices. When paddings look inconsistent at a specific viewport width, check whether a layout is silently changing shape there before assuming it's just a missed style.
- **Content-reveal patterns (accordions, tap-to-expand) default to mobile-only.** Both the CX/Strategy offers and the four-forces cards initially applied their reveal behavior at all breakpoints; in both cases the actual density problem was mobile-specific, and hiding already-well-laid-out desktop/tablet content behind taps added friction without solving anything. The working technique: keep the JS toggle state, but add `min-[701px]:!max-h-none` (or equivalent) to force full visibility above 700px regardless of state.
- **When a reveal-on-tap teaser hides content, keep enough visible to judge relevance.** First pass at the CX/Strategy accordion hid the image and lead paragraph along with the deep copy; the fix was to keep eyebrow + headline + image + bolded lead always visible and only hide the deeper body copy behind the toggle.
- **Testimonial truncation is mobile *and* tablet**, clamped to roughly the shortest quote's length with a Read more/Show less toggle; desktop always shows full quotes at natural height. (This was mobile-only in the previous session's notes — extended to tablet after `SpeakingTestimonials` showed the same uneven-card-height bug there.) When a "let the shortest one show fully" exception is used, verify it actually stays shortest given that *specific* component's font-size and padding — `WwmTestimonials`' larger type meant the "shortest" quote didn't actually fit in fewer lines than the clamp cap, so it defeats the purpose there; component-specific verification, not copy-paste, is required.
- **For narrow-column two-part layouts (label + description), stack instead of placing side-by-side.** Freed up real space on the Case Study card backs, not just cosmetic — a fixed-width label column steals horizontal room from the description, forcing more wrapped lines.
- **Never overwrite an image file in place.** Always save under a brand-new filename.
- **Tailwind v4 cascade gotcha:** plain CSS targeting a bare HTML tag in `globals.css` must be wrapped in `@layer base { ... }` or it beats every layered utility class regardless of specificity.
- **Case Study/Quest cards alternate in display order** (not grouped by type) and use a rotated tape-strip tag overlapping the card's top edge.
- **Dropped source images live in `design-reference/assets/`, not `public/assets/`** — copy into `public/assets/` under a distinct filename before they'll render.
- **Git author** is set at the repo level to `4304091+aribajahan@users.noreply.github.com` — don't let this drift back to a hostname-based auto-detected email.
- **Reading Room stays untouched** until Ariba explicitly says to start it.
- **Be proactive about spacing/rhythm consistency, not reactive.** Ariba flagged this directly this session — check padding/margin consistency as part of finishing a section, not after she points it out.
